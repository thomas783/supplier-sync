# 보류된 설계 결정 모음

지금 구현하지 않기로 한 것들의 목록입니다. "하지 않은 것"에도 이유가 있어야 한다는 원칙에 따라, 각 항목에
보류의 근거와 — 논의가 이미 진행된 경우 — 도입 시점의 출발점이 될 초안을 함께 남깁니다. 결정 과정의 상세한
흐름은 `JOURNAL.md`에 있습니다.

## 재시도 정책 · 서킷 브레이커 — 구현됨

두 항목은 구현·활성화되어 있습니다. 상세(재시도 대상 집합·경로별 예산·대기 산정·서킷 7축·적용 순서)는
[INTEGRATION.md](INTEGRATION.md)가 단일 원천입니다 — 여기서는 이 문서가 "보류 목록"이므로 지위만
남기고 상세는 위임합니다. 코드는 `SupplierResilience`·`application.yml`의 `resilience4j` 구성, 지표는
`circuit_open`·`rate_limited` outcome([MONITORING.md](MONITORING.md))입니다.

## 요금·재고 캐시 전략과 숙소 수천 개 대응 — 논의 완료·설계 확정, 구현만 보류

숙소가 수천 개로 늘면 "검색 시 전량 실시간 조회" 구조는 지연이 N에 선형이라 유지가 어렵습니다 — 청크 수 =
공급사 수 × ⌈N/50⌉이고, 동시성 상한은 폭주를 막을 뿐 지연을 줄이지 못합니다.

**재논의를 마쳤고 결론을 두 문서로 확정했습니다** — 단계 로드맵(청킹·지표 → TTL 캐시 → 스냅샷)과 발동
조건은 [INTEGRATION.md](INTEGRATION.md)에, 캐시의 흐름 설계(단위와 키, TTL = 정합성 오차 허용 범위,
스탬피드 계층화, 규모별 단위 전환)는 [CACHING.md](CACHING.md)에 있습니다. **구현은 여전히
보류입니다** — 전환 트리거(검색 p95 초과 또는 429 관측)가 발동하는 시점에 확정된 설계대로 도입합니다.

## 중복 상품 병합 — 설계 확정, 구현 예정

두 공급사가 같은 숙소를 각자 코드로 팔아도 공통 키가 없어, 지금은 별개 상품으로 나란히 노출됩니다.
카탈로그 테이블로 사전 매핑해 숙소 1개 + 공급사별 오퍼 그룹으로 내리는 설계를 확정했습니다(매칭 정밀도
우선, 가산적 병합, v2 응답 계약). 상세는 [MERGE.md](MERGE.md).

## 환율·다중 통화 처리 — 설계 확정, 구현 예정

현재 범위는 KRW 단일이라 환산이 no-op 입니다. 외화 공급사 도입 시 표준 `Price` 에 환산가(KRW `Long`)·
원가(로컬 `BigDecimal`)·환율을 나란히 두고, 정규화 단계에서 환산(내림)하는 설계를 확정했습니다. 상세는
[CURRENCY.md](CURRENCY.md).
